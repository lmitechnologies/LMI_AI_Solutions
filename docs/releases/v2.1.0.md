# Release Notes — v2.0.1 → v2.1.0

## Breaking Changes

- **`lst_to_json` links keypoints to boxes.** Each keypoint gets the `bounding_box_id` of the box it is nested under in Label
  Studio, else of the one box that contains it. Conversion fails if a keypoint is in no box or in several, is nested under
  something other than an upright box, or repeats a name on its box. Fix the nesting, or pass `--keep_unlinked_keypoints` to keep
  the old behavior. `json_to_lst` writes the links back as nesting.
- **`lst_to_json` keeps fractional pixels.** Box corners and polygon points are no longer truncated, so labels can shift by up to
  a pixel from earlier conversions. Related changes:
  - `json_to_yolo` pose export rejects keypoints linked to, or unlinked inside, a rotated target box.
  - `json_to_yolo --seg` box masks cover the pixels whose centers are inside the box.
  - Padding, cropping and `apply_ops crop-by-label` cut polygons and rotated boxes at the edge instead of moving corners onto it.
    Shapes fully outside are dropped; a polygon split by the edge becomes `<id>_p0`, `<id>_p1`, ….
  - `crop-by-label` now keeps keypoints, and fails on a rotated crop box, a non-box crop label, or a crop that covers no pixel.
  - `dataset_pad.clip_shapes` returns the clipped shapes instead of ids to delete. `crop_dataset_by_label` drops `clip`;
    `crop_kp`, `crop_bbox`, `crop_mask` and `crop_by_percent` are removed.
- **`tile_step` moved** ([#469](https://github.com/lmitechnologies/LMI_AI_Solutions/pull/469)): use
  `from lmi_common.infer_cli import tile_step`. `TILE_PLOT_DIR` and `predict_tiled` stay in `object_detectors.od_core.infer_cli`.
- **Tile plots moved** ([#469](https://github.com/lmitechnologies/LMI_AI_Solutions/pull/469)): tiled `infer.py` saves them to
  `_tile_plots/` instead of `tiles/`.
- **Pose `predictions.json` names keypoints by slot** from the model's `kpt_names`, instead of by their box's class. Models
  without `kpt_names` give `"0"`, `"1"`, ….

## New Features

- **Keypoint names:** `json_to_yolo` writes `kpt_names` to `dataset.yaml`; `YoloPose.kpt_names` reads them from a `.pt` or
  exported model.
- **Classifier tiling and confidence** ([#469](https://github.com/lmitechnologies/LMI_AI_Solutions/pull/469)):
  `ClassifierBase.predict()` takes `operators` (tile scores merged by weighted vote) and `confidence` (float or per-class dict;
  images below it get `None`). The YOLO classifier `infer.py` adds `-c`, `--tile` and `--stride`.

## Deprecations

- **CSV label tools** ([#468](https://github.com/lmitechnologies/LMI_AI_Solutions/pull/468)) moved to
  `lmi_utils.label_utils.csv_labels`. Old paths still work with a `FutureWarning` and will be removed later.

  | Deprecated | Use instead |
  |---|---|
  | `lst_to_csv`, `csv_to_yolo`, `csv_to_coco`, `csv_to_lst` | `lst_to_json`, `json_to_yolo`, `json_to_coco`, `json_to_lst` |
  | `resize_with_csv`, `pad_with_csv`, `rot90_with_csv` | `apply_ops resize`, `apply_ops pad`, `apply_ops rotate` |
  | `plot_with_csv` | `plot_with_json` |
  | `csv_utils`, `shapes` | `lmi_utils.dataset_utils.representations` |

  Tools with no json version yet keep working; convert their output with `csv_to_json`. Label Studio → YOLO now looks like:

  ```bash
  python -m lmi_utils.label_utils.lst_to_json -i $input_path -imgs $input_path -of $input_path/labels.json
  python -m lmi_utils.label_utils.apply_ops -i $input_path -oi /app/data/resized resize --width $W --height $H
  python -m lmi_utils.label_utils.json_to_yolo -ti /app/data/resized -o /app/data/resized_yolo --seg
  ```

- **detectron2 `csv_to_coco` layout:** the trainer now reads the `json_to_coco` layout (`_annotations.coco.json` beside the
  images). The old layout still trains with a `FutureWarning`.
